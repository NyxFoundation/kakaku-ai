# データスキーマ

## 設計の芯

**過去のファイルを書き換えない。** 週次クロールは
`data/snapshots/<YYYY-MM-DD>/` に新しいディレクトリを 1 つ足すだけ。
xlsx は毎回「全スナップショットを読み直して組み直す」ので、
時系列は勝手に伸びていく。

```
data/
├─ snapshots/
│  ├─ 2026-08-22/
│  │  ├─ auction_listings.jsonl   落札 1 台ずつ（生）
│  │  ├─ price_by_year.jsonl      車種 × 年式 の相場（メイン系列）
│  │  ├─ vehicle_summary.jsonl    車種単位のサマリ
│  │  ├─ reviews.jsonl            口コミ個票
│  │  ├─ review_summary.jsonl     車種 × 年式 の口コミ集計
│  │  ├─ recalls.jsonl            国交省リコール
│  │  ├─ defects.jsonl            国交省 不具合情報（個票）
│  │  ├─ defect_summary.jsonl     装置別の不具合集計＝壊れやすい点
│  │  ├─ wide_summary.jsonl       全車種の車種単位サマリ（カタログ兼用）
│  │  ├─ wide_by_year.jsonl       全車種 × 年式 の小売相場
│  │  ├─ classic_listings.jsonl   旧車の在庫 1 台ずつ
│  │  └─ classic_auctions.jsonl   旧車のヤフオク落札 1 台ずつ
│  ├─ 2026-08-29/
│  └─ …
├─ cache/                        取得した生レスポンス（git 管理外）
├─ catalog.jsonl                 車種カタログ（全車種クロールが育てる）
└─ xlsx/
   ├─ all_cars.xlsx              全 2,237 車種のカタログと年式別相場
   ├─ standard_cars.xlsx         乗用車（ミニバン・トラックを除く）
   ├─ minivan_souba.xlsx         ミニバン（深掘り20車種）
   └─ classics_90s.xlsx          1988〜2001年式の旧車
```

xlsx のファイル名は変えない。Drive の共有 URL はファイル名に紐づいていて、
同じ名前に上書きすれば rclone が既存ファイルを update するのでファイル ID が
変わらず、共有済みの URL がそのまま生きる。改名すると新しいファイルになり、
旧 URL を共有した人には古い中身が見え続ける。`minivan_souba` は対象が
トヨタミニバンから 7人乗りミニバン全体に広がったあとも、`classics_90s` は
1988〜2001年式を指すようになったあとも、名前はそのままにしてある。

JSONL にしたのは、1 行 1 レコードで追記・grep・部分再処理がやりやすいから。
CSV と違って列が増えても既存行を壊さない。

## price_by_year — メイン系列

粒度: **1 行 = スナップショット日 × 車種 × 年式**

| 列 | 意味 |
|---|---|
| `snapshot_date` | 取得日（= 「2026/xx/xx 時点」の xx） |
| `vehicle_key` / `vehicle_name` | 車種 |
| `generation` | 世代（年式から車種マスタで解決） |
| `model_year` | 年式（西暦） |
| `auction_n` | ヤフオク落札件数（実走行・修復歴なしのみ） |
| `auction_min/p25/median/mean/p75/max_manyen` | 落札価格の分布（万円） |
| `auction_median_mileage_km` | 落札車の走行距離中央値 |
| `retail_n` | カーセンサー掲載台数 |
| `retail_p25/median/mean/p75_manyen` | 小売価格の推定分布（万円） |
| `retail_minus_auction_manyen` | 小売中央値 − 落札中央値 |
| `retail_premium_pct` | 上を落札中央値で割った % |

この 1 テーブルだけで

* 最新断面 → `snapshot_date` でフィルタ
* 時系列推移 → `(vehicle_key, model_year)` でグループ、`snapshot_date` で並べる
* 年式別の値落ち曲線 → 1 スナップショット内で `model_year` 順に並べる

が全部できる。xlsx の「推移_落札中央値」シートは 3 つ目をピボットしたもの。

### 相場の作り方

**オークション（ヤフオク!）**
`carSpec.modelDate` を年式として、落札価格をそのまま集計する。
メーター交換車（`mileageType != REAL_MILEAGE`）と修復歴あり（`repairType != NONE`）は
主系列から外し、件数だけ `excluded_n` に残す。窓は「終了180日間」。

**小売（カーセンサー）**
相場ページの「価格帯 × 年式」度数分布から、ビン内一様分布を仮定した
グループ中央値・四分位を補間する。最上位ビン「420万円以上」は上端不明なので
幅 20 万円と仮定している（`OPEN_TOP_WIDTH`）。台数が少ない帯なので中央値への
影響は小さいが、平均には効く。

### 車種単位でまとめるときの注意

`price_by_year` は年式で揃っているので、同じ年式どうしの比較は素直にできる。
一方で**車種単位に畳むときは年式構成を揃えないと嘘になる**。落札は古い年式、
掲載は新しい年式に偏っているためで、`charts.vehicle_sheet` では落札の年式
ヒストグラムを重みにして小売側を揃えている。

走行距離も揃っていない。カーセンサーの相場ページ 2 枚目（価格帯 × 走行距離）から
掲載車の走行距離中央値を取って `vehicle_summary.carsensor_retail_median_mileage_km`
に入れてあるので、落札車の距離と並べて読むこと。

### 精度について正直なところ

年式によっては落札が 1〜2 台しかない。`auction_n` を必ず見て判断すること。
週次でスナップショットが積み上がるので、複数週をまとめれば実効サンプルは増える。
落札の窓は 180 日で毎週重なるが、`auction_id` を `auction_listings` に残してあるので
「新しく落札された分だけ」を後から差分抽出できる。

## vehicle_summary — 車種単位

1 行 = スナップショット日 × 車種。カーセンサー由来は `carsensor_` 、
価格.com 由来は `kakaku_` で接頭辞をつけて混ざらないようにしてある。

主なもの: 新車価格レンジ、中古価格レンジ、掲載台数、取扱店舗数、
総合評価、口コミ件数、デザイン/走行性/居住性/運転しやすさ/積載性/維持費、
ミニバン内ランキング。

## reviews / review_summary — 口コミ

みんカラのレビュー個票。1 件に年式・グレード・おすすめ度・6 軸スコア・
満足点・不満点・総評が入る。`review_summary` は年式で畳んだもの。

## defects / defect_summary — 壊れやすい点

国交省の不具合情報（ユーザー通報）。個票には型式・初度登録年月・
総走行距離・症状の要約が入る。

`defect_summary` は **世代 × 不具合装置** で畳んだもの。年式そのままだと
1 件ずつに散って読めなくなるので、車種マスタの世代でまとめている。
あわせて `generation = （車種全体）` のロールアップ行も出すので、
ざっくり見たいときはそこだけ拾えばいい。

| 列 | 意味 |
|---|---|
| `defective_device` | 不具合装置（エンジン / 燃料装置 / 制動装置 …） |
| `report_count` / `share_pct` | その世代のなかでの通報件数と構成比 |
| `median_mileage_km` | **発生時の走行距離の中央値** ← 整備タイミングの目安 |
| `model_year_min` / `max` | 通報された個体の初度登録年のレンジ |
| `model_codes` | 該当した型式 |
| `examples` | 直近 3 件の実際の症状の文章 |

## recalls

国交省リコール届出。届出日・不具合装置・対象台数・型式・
「不具合の状況」「改善措置」の全文つき。中古車を見るときは
「この個体はこのリコールを消化済みか」を販売店に確認する材料になる。

## 週を重ねたときに何ができるか

1. **値落ちの追跡** — 同じ (車種, 年式) の落札中央値が週ごとにどう動くか
2. **年式間の比較** — ある時点での年式別カーブ。どこに「お買い得の谷」があるか
3. **小売プレミアムの変動** — 業販と小売の差が開く/縮まる局面
4. **在庫と価格の関係** — `retail_n` と `retail_median_manyen` を並べる
5. **不具合の蓄積** — `defect_summary` は毎週フル取得なので、
   件数の増分＝その週に新しく通報された不具合
